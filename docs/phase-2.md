# Phase 2: reproducible bootstrap implementation

Implemented 2026-09-28. Development and execution tests used disposable marked
fake homes under `/tmp`, not the live home. No live configuration, plugin,
theme, package, service or Omarchy installation was changed; no symlinks,
dotfiles commits, pushes or GitHub repositories were created.

## Architecture and flow

Bash entry points require Python 3.11+ and dispatch to a shared standard-library
engine. `policy.py` validates manifests, profile selections and payload safety;
`deploy.py` implements checked Git sources, atomic file copies, journals and
guarded rollback. `select.sh` uses Gum if present or numbered Bash prompts.
Component wrappers use the same planner and `--only` scope, so conflict/source
gates cannot be bypassed by choosing a different component entry point.

The flow is environment check, explicit machine profile, package components,
manifest-driven optional plugin selection, theme-source selection, configuration
plan, confirmation, application and verification. Default plugins are automatic;
optional ones are chosen; host ones require profile membership; excluded ones
are never installed; pending decisions fail rather than becoming guesses.

All 63 native and 8 AUR inventory packages are mapped once into 15 components.
These retain conceptual system, development, desktop, CLI/productivity, optional
and hardware categories. Native packages use `--needed`; existing packages are
not duplicated. No packages are removed. AUR helpers are not bootstrapped;
source review is interactive and missing AUR packages block unattended use.
Native unattended application uses explicit selections, `sudo -n` and pacman's
`--noconfirm`. Full-system upgrades are not hidden inside this installer.

Profiles are portable explicit IDs, never inferred hostnames. Selection records
carry components, optional plugins, themes, host IDs/files, scope, exact plugin
revisions, compatibility decisions and policy/payload/overlay digests.
`--save-profile` exports a verified selection without overwriting an existing
profile. `--replay` refuses drift. See host-profiles.md for the exact TOML form.

Configuration is an explicit allowlist, not recursive mirroring or symlinks.
Identical files and exact clean checkouts are no-ops. Conflicts fail unless the
operator explicitly authorizes backed-up replacement. Symlink destinations,
dirty repositories and mismatched Git origins/revisions are always rejected.
Sources are staged before package/configuration application; pins never become
HEAD. Plugin IDs/schema/entry points and source-tree safety are validated.
Credentials remain local setup requirements, not copied dependency metadata.

Themes are pinned source clones only, not activated or regenerated by this
installer. Mise uses the audited exact `tool@version` pins, never latest or
implicit upgrades/pruning. Compatibility compares pacman versions of Omarchy,
Quickshell and Hyprland with compatibility.toml; mismatches need an explicit
risk decision and do not certify a new version.

## Recovery

Write-ahead journals and reviewed configuration backups live in the separate
`~/.local/state/omarchy-dotfiles/backups/<run-id>/` namespace. A failed application
prints a failed journal and does not write a successful selection record.
Rollback first validates every target: it restores safe originals, removes only
unchanged installer-created files and relocates new clean source checkouts to
the journal's recoverable retired directory. It refuses subsequent edits and
shares an exclusive lock with installation. Dry-run rollback changes nothing.
An unchanged rerun creates no empty journal.
Packages/tools and exported repository profiles are not undone. External
package/tool changes are not a fully atomic transaction.

## Isolated verification

Command: `python3 -B -m unittest discover -s tests -v`.
The final suite contains 41 tests and passed. Real file copies, local Git
cloning/checkouts, source validation, selection export/replay and rollback were
exercised. Pacman/AUR/mise operations were mocked; no real package/tool
installation was attempted.

Coverage includes first and idempotent application, no-write dry run, minimal
defaults, optional selection, exclude/undecided behavior, all-mode policy,
explicit host membership, configuration conflicts/backups, rollback/dry rollback,
refusal of subsequent edits, partial-failure journal recovery, absent Gum/Bash
fallback, missing AUR helper, unattended AUR review gate, mocked package/tool
application, malformed manifests, incompatible versions/explicit override,
dirty sources, wrong plugin identity, missing/mismatched pins, theme sources and
blocked provenance, profile/digest replay, doctor, notification ownership,
Neovim lockfile deployment, secret/credential URL rejection, runtime paths,
machine paths and held monitor overlays.

Crucially, the actual inventory was also exercised in a fake home: a complete
minimal dry run fails on the three real unresolved default-plugin pins, without
deployment. Explicit config-only application succeeds without touching shell,
Hyprland or plugin directories. No policy was changed to make tests pass.

Static checks: 13 JSON/TOML files parse, Bash entry points pass `bash -n`, Python
modules parse, and Ruff passes with cache/fixing disabled. Whitespace checks
include direct no-index checks because the repository is entirely untracked.
Pattern scans find no real keys/tokens; the only credential-shaped URL is an
intentional dummy negative-test input. Absolute home paths in new code are a
scanner expression and a synthetic rejection test, not deployment paths.
No generated/runtime/cache payload was added. These checks are not an exhaustive
security review of third-party executable code.

## Not certified in isolation

- Real pacman/AUR availability, sudo authorization, PKGBUILD review, remote commit
  availability and mise downloads/artifact integrity.
- Real Gum terminal rendering, Wayland/Hyprland parsing, Quickshell loading and
  hot reload, notification D-Bus/IPC ownership and graphical behavior.
- Account/OAuth setup, Docker permissions/services, printers, GPU/display
  behavior and optional external plugin engines/assets.
- Theme application/sanitization and generated colors/backgrounds through
  Omarchy; Neovim runtime plugin initialization and editor behavior.

Doctor checks policy and selected files/sources/tool versions, required commands,
managed broken links, shell schema/inventory references and notification-owner
configuration. It explicitly does not certify real runtime behavior.

## Remaining gates and exact Phase 3 recommendation

1. Review/test the Hijri Calendar changes in its separate repository and obtain
   a canonical committed revision; do not reset the live copy.
2. Normalize Daily Islamic Reminder's temporary remote, dirty source and cache
   separation in its independent project; obtain a reviewed available pin.
3. Choose whether to preserve Omapager's click patch via an independent fork or
   use a reviewed upstream revision, then explicitly choose notification service
   ownership. No such choice or source mutation was inferred in Phase 2.
4. Review fresh-install Hyprland Lua versus the recorded `.conf` include graph,
   shell/bar layout, Workspace Names shortcuts and a real monitor/GPU profile.
   Bash snapshots likewise need a dependency/include review. They remain
   quarantined, not silently treated as portable deployment files.
5. Resolve selected-plugin runtime prerequisites and Omastorm engine/artifact
   pinning; determine whether exact pacman/AUR artifact snapshots are required.
6. Run a complete installation, second installation, doctor and recovery in a
   disposable fresh Omarchy VM/session. Approve a deployable profile and desktop
   activation policy only after those results. Do not start a custom bar or
   deploy to the audited live home before this acceptance gate.

The Phase 2 framework is implemented; recreating the full preferred desktop is
not yet certified or unblocked. Existing monitors/configuration are preserved.
Repository status remains untracked/uncommitted with no publishing actions.
